所有操作从左侧「连接」树开始。本教程演示新建一个 SQLite 连接；PostgreSQL / MySQL 只是表单字段不同。

## 1. 打开新建连接对话框

点击左侧树顶部的 **＋** 按钮。

![主界面总览](/images/01-workspace-overview.png)

## 2. 填写连接信息

![新建连接对话框](/images/02-connection-dialog.png)

| 字段 | 说明 |
|---|---|
| 名称 | 必填，≤100 字符，树节点显示名 |
| 类型 | PostgreSQL / MySQL / SQLite |
| 主机 / 端口 | 非 SQLite 必填；端口占位符按方言自动提示（5432 / 3306） |
| 用户名 / 密码 | 非 SQLite 必填；编辑已保存连接时密码留空表示「保持不变」 |
| 默认数据库 | 非 SQLite 可选，展开树时的默认库 |
| 数据库文件路径 | 仅 SQLite：本机 `.db` 文件的绝对路径 |
| 只读模式 | 打开后该连接拒绝所有写操作（详见下文） |

本教程填入：名称 `Demo 商城`、类型 `SQLite`、路径 `/Volumes/code/Ark/data/demo/shop.db`。

![填写 SQLite 表单](/images/03-connection-form-sqlite.png)

## 3. 测试连接

点击 **测试连接**，成功会内联显示服务器版本与耗时（如 `连接成功：SQLite 3.46.1 (3ms)`），失败则显示红色错误详情，不会创建连接。

![测试连接成功](/images/04-connection-test-ok.png)

点击 **创建** 保存。连接配置写入服务端 `data/ark.db`，密码使用 ASP.NET Data Protection 加密，接口永不回显（只有 `hasPassword` 标记）。

## 4. 只读模式

打开「只读模式（拒绝所有写操作）」开关后，该连接受三层防护：

1. SQLite 直接以只读方式打开文件（文件系统级兜底）
2. SQL 白名单：仅允许 `SELECT / WITH / EXPLAIN / SHOW / PRAGMA` 等只读关键字，写语句返回 403（错误码 2004）
3. DDL 执行与数据变更提交前均前置检查

适用场景：把生产库挂进来只做查询分析。

## 5. 编辑与删除连接

在树中**右键连接**：

- **编辑连接**：重新打开表单；修改后立即生效
- **删除连接**：仅删除 Ark 中保存的连接配置，**不影响数据库本身**；删除前有确认弹窗

## 常见问题

- **SQLite 连接报「无法打开数据库文件」**：检查路径是否存在、进程是否有读权限；只读模式下文件不存在时不会自动创建
- **测试连接成功但树展开失败**：检查账号是否有目标库的元数据权限（MySQL 需要 `information_schema` 读取权限）
- **密码忘了能不能找回**：不能。密码加密存储且无回显接口，只能重新录入
